# Fabric или NeoForge: что выбрать

Сравнение под твою задачу: **новичок, хочешь научиться и сделать свой мод**.
Данные на **6 октября 2026**. Документацию обоих загрузчиков я читал по исходникам на GitHub
([FabricMC/fabric-docs](https://github.com/FabricMC/fabric-docs), правка от 30.09.2026;
[neoforged/Documentation](https://github.com/neoforged/Documentation), правка от 01.10.2026),
версии сверял поиском и по тегам репозиториев.

---

## Главное, что поменялось в 2026 году (касается обоих)

1. **Новая нумерация Minecraft.** После 1.21.11 идут версии вида «год.номер»: 26.1 (март 2026),
   26.2, **26.3 — текущая (вышла 15.09.2026)**, 26.4 ожидается в конце года.
2. **Minecraft больше не обфусцирован.** С 26.1 код игры поставляется с настоящими
   именами классов и методов (`Item`, `BlockState`, `Player`…). Раньше Fabric и Forge называли одни
   и те же классы по-разному («маппинги» Yarn и Mojang), и примеры из разных источников
   не совпадали. Теперь имена у всех одинаковые. Для новичка это огромный плюс:
   любой пример из любого источника читается одинаково.
3. **Нужен JDK 25.** Minecraft 26.x требует Java 25 — и Fabric, и NeoForge пишут это
   первым пунктом в «Начале работы».
   ⚠️ **В курсе сейчас JDK 21**: он нужен был для Minecraft 1.21.x. См. вопрос в конце.
4. **Старые туториалы почти бесполезны.** Всё, что написано под 1.21.11 и раньше, расходится
   с 26.x в именах. Учимся только по официальной документации и коду её примеров.

## Сравнение

| Критерий | Fabric | NeoForge |
|---|---|---|
| **Поддержка Minecraft 26.3** | Стабильная с дня выхода: Fabric API `0.160.x+26.3` вышел 14.09, к 06.10 уже `0.162.0+26.3` | На середину сентября — только `26.3.0.1-beta`; стабильная последняя — 26.2. Обычно отстаёт от выхода игры на недели |
| **Документация** | [docs.fabricmc.net](https://docs.fabricmc.net): 105 страниц, **91 переведена на русский**. Каждый пример взят из рабочего мода в репозитории — код компилируется | [docs.neoforged.net](https://docs.neoforged.net): 78 страниц, **только английский**. Подробнее про внутреннее устройство игры, но местами справочник, а не учебник |
| **Свежие материалы** | Больше: Fabric — самый скачиваемый загрузчик на свежих версиях (около трети загрузок), больше открытых модов на 26.x | Меньше, но крупные контентные моды и сборки переходят на NeoForge |
| **Шаблон первого мода** | Генератор на сайте [fabricmc.net/develop/template](https://fabricmc.net/develop/template/) | Генератор [neoforged.net/mod-generator](https://neoforged.net/mod-generator/) |
| **Первая сборка** | Быстрая: игра не перекомпилируется | Долгая в первый раз: NeoForge пропатчивает исходники игры (документация пишет: до часа) |
| **Регистрация предмета** | `Registry.register(...)` в статическом поле, просто «объект в реестр» | `DeferredRegister` + `Supplier`, обращение через `.get()` — нужно понимать обобщения и лямбды |
| **События** | Колбэки Fabric API: `PlayerBlockBreakEvents.AFTER.register((...) -> ...)` | Шина событий: `@SubscribeEvent` и классы событий |
| **Клиент и сервер** | Шаблон с сайта может делить код на `main` и `client` (так устроен и пример в документации) — новичку надо сразу понять, что куда | Один `src/main`, разделение — через аннотации и проверки |
| **API «из коробки»** | Fabric минималистичен: многое даёт Fabric API, остальное — через миксины | Больше готовых хуков, меньше миксинов |
| **Тесты в моде** | `fabric-loader-junit`: обычные JUnit-тесты с **настоящими реестрами** Minecraft. Плюс серверные и клиентские GameTest, запускаются в `gradle build` и на GitHub Actions — всё описано в доке | Через ModDevGradle `neoForge { unitTest { enable() } }` — JUnit с классами игры, можно поднять тестовый сервер. GameTest тоже есть. Описано в README ModDevGradle, а не в основной документации |
| **Сложность первого мода** | Предмет с текстурой: 1–2 класса Java + 3 JSON (модель, «клиентский предмет», перевод) + PNG | Те же 3 JSON + PNG (форматы ресурсов задаёт игра, а не загрузчик); Java — класс с `DeferredRegister` и подключение к шине мода |
| **Переход на Kotlin** | Официальный `fabric-language-kotlin` | Официальный Kotlin for Forge (KFF) |

### Что это значит для курса

- **Скорость обратной связи.** Ты будешь много раз запускать игру. На Fabric первая сборка
  и перезапуск быстрее.
- **Русский язык.** Перевод документации Fabric — прямой бонус. Пересказываем мы своими словами,
  но сверяться со своим языком проще.
- **Проверка мод-чекпоинтов.** Для курса важно: Fabric прямо в официальной документации
  показывает, как писать JUnit-тесты с реестрами и как запускать GameTest в CI. Это ровно то,
  что нужно, чтобы чекпоинты проверялись кнопкой Check. У NeoForge это тоже возможно,
  но описано хуже.
- **Порог по Java.** Fabric-код первого мода использует только то, что будет пройдено к
  разделу 3 (классы, статические поля, наследование). На NeoForge сразу появляются `Supplier`,
  `DeferredHolder<Item, Item>` и `.get()`. Это лямбды и обобщения из разделов 4–5.
- **Своевременность.** Fabric выходит под новые версии игры почти сразу. Курс будет жить
  долго: важно, чтобы при обновлении Minecraft загрузчик не задерживал работу.

## Рекомендация

**Fabric** — для этого курса и для первого мода.

Почему: поддержка 26.3 с первого дня, документация на русском с компилируемыми примерами,
JUnit-тесты с реестрами описаны в документации (это нужно для проверки чекпоинтов) и
более низкий порог по Java к разделу 3.

Когда выбрать **NeoForge**: если хочешь делать **большой контентный мод** для сборок
с другими крупными модами (техника, магия, сложные машины) или твои друзья играют на
NeoForge-сборках. Тогда переход с Fabric на NeoForge после курса займёт пару вечеров:
имена классов игры теперь одинаковые, отличается только «клей» загрузчика.

Решение за тобой. После выбора поменяю раздел 3 в `PROGRAM.md`: план написан под Fabric,
для NeoForge там помечено, что заменить.
