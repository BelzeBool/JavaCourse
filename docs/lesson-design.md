# Как писать уроки

Руководство для автора. Цель — не «куча текста подряд», а учебник, который ведёт по шагам:
коротко объясняет, сразу даёт попробовать, проверяет и не перепрыгивает через темы.

Эталон — **урок 1.2 «Переменные и типы»** (`s01_basics/l02_variables`). Если что-то в этом
руководстве непонятно — смотри, как это сделано там.

---

## 1. Что берём из примеров и чего избегаем

Разобраны две страницы-примера: «this и иерархия классов» и «Ключевые слова Java».

**Берём:**

| Приём | Как у нас |
|---|---|
| Под кодом — «По-русски»: что делает код, обычными словами | компонент `k-ru` |
| Интерактивная схема: кнопки «Дальше/Назад», видно, что лежит в памяти и что на экране | компонент `k-trace` |
| «Разбери строку»: нажал на слово — получил объяснение | компонент `k-anatomy` |
| Настоящая ошибка компилятора + перевод + как чинить | компонент `k-error` |
| В конце: «Коротко» и «Проверь себя» | шаг «Итог урока»: `k-recap` + `details.k-self` |
| Смысловые цвета: один цвет — одно значение | тип — синий, имя — оранжевый, значение — зелёный, ошибка — красный, моды — фиолетовый |

**Избегаем:**

| В примерах | Почему плохо | Как у нас |
|---|---|---|
| Пять тем на одной странице (this, иерархия, конструкторы, super, порядок инициализации) | Новичок тонет: не за что зацепиться, нечего отработать | Одна идея — один шаг. Эти пять тем — четыре урока по 10 шагов |
| В примерах про `this` уже есть `static`, `abstract`, интерфейсы, исключения, лямбды | Объяснение опирается на то, чего ученик ещё не знает | Карта понятий `docs/concepts.yaml` + проверка `tools/check_order.py` |
| Метафоры меняются каждый абзац: коты, пицца, телефон, дом, бабушкин рецепт | Каждая новая метафора — ещё одна вещь, которую надо понять | Одна сквозная метафора на понятие, из Minecraft (раздел 5) |
| Блоки «Глубже»: байткод, `aload_0`, `invokespecial` | Новичку рано, отвлекает | Только в ⭐-шагах «для любопытных», и только после основной темы |
| «Проверь себя» — только раскрыть ответ | Ученик читает, а не делает | Вопросы с кнопкой Check и задачи с тестами после каждой идеи |
| Раскладка на 1100 px, две колонки | Панель задания в IDE — 400–600 px | Всё в одну колонку, картинки 480 px |
| Шрифты из интернета | Курс должен работать офлайн | Системные шрифты IDE |

## 2. Двенадцать правил

1. **Одна идея — один шаг.** Шаг-теория — не больше ~300 слов и двух экранов панели.
   Хочется больше — значит, это два шага.
2. **Сначала «зачем», потом «как».** Первый абзац — проблема из Minecraft, которую решает идея.
   «Алмазов то 3, то 12 — где программе это помнить?»
3. **Пример → предскажи → сделай сам.** После теории — сразу вопрос «что напечатает?»,
   потом задача «как в примере», потом задача, где надо подумать.
4. **Не скакать.** Каждое понятие вводится до того, как используется. Проверяет `tools/check_order.py`.
   Если нужно показать заранее — это осознанное решение с пометкой `<!-- preview: … -->` и фразой
   «подробно — в уроке N».
5. **Заклинания помечаем честно.** То, что ученик пишет раньше, чем понимает (`public static void main`,
   `String` с большой буквы, `new Scanner(System.in)`), сопровождается плашкой «Пока просто запомни»
   и обещанием, где объясним. Обещание обязано сбыться — оно записано в `concepts.yaml` (`explained`).
6. **Одна метафора на понятие, сквозная через весь курс.** Список — в разделе 5. Новую метафору
   добавляем туда же, прежде чем использовать.
7. **Код короткий.** Блок кода — до 12 строк. Под каждым блоком — вывод программы (`k-console`)
   или «По-русски» (`k-ru`).
8. **Ошибки — часть урока.** В каждой теме — 1–2 настоящие ошибки компилятора: код, сообщение,
   перевод, как чинить. Сообщение копируем из настоящего `javac`, не по памяти.
9. **Картинка — когда есть состояние или процесс**: что где лежит, в каком порядке, из чего состоит.
   Не украшение. Интерактив — когда процесс идёт во времени (трассировка) или строку надо разобрать
   по частям.
10. **Повторение.** В конце урока — «Проверь себя» на всё в уроке. В начале следующего урока
    одна из первых задач использует прошлую тему.
11. **Факты Minecraft — для версии 1.21.1** и проверены: здоровье 20 = 10 сердечек, стак 64,
    зачарование тратит 1–3 уровня. Сомнительный факт сверяем с Minecraft Wiki.
12. **Тон.** На «ты», коротко, без воды. Без глаголов прошедшего времени с родом про ученика:
    не «ты нашёл», а «у тебя есть», «нашлось», «Стив нашёл». Не «сам/сама» — «придумываешь ты».

## 3. Как устроен урок

Урок — 8–14 шагов, ~45–90 минут. Темп свободный: урок можно бросить на любом шаге и вернуться.

**Ритм:** не больше двух шагов теории подряд. После каждой идеи — действие.

| Роль шага | Тип | Пример из 1.2 |
|---|---|---|
| Зацепка + первая идея | 📖 theory | «Переменная — сундук с табличкой» |
| Быстрая проверка понимания | ❓ choice | «Имя или текст?» |
| Задача «как в примере» | 🛠 edu | «Первая переменная» |
| Следующая идея | 📖 theory | «Склейка», «Типы» |
| Проверка | ❓ choice | «Что не так с типом?» |
| Задача, где надо подумать | 🛠 edu | «Карточка игрока» |
| Идея с процессом во времени | 📖 theory + `k-trace` | «= значит положи» |
| Трассировка в уме | ❓ choice | «Сколько стрел?» |
| Задача с запретом на обход | 🛠 edu | «Уровень опыта» (12 и 9 считает программа) |
| Детали и хорошие привычки | 📖 theory | «Имена и константы» |
| Задача «почини» | 🛠 edu | «Почини сундуки» |
| Итог | 📖 theory | `k-recap`, словарик, «Проверь себя», что дальше |

**Названия шагов** (`custom_name`): теория — сутью («Переменная — сундук с табличкой»),
вопрос — «Вопрос: …», задача — «Задача: …». Плагин сам показывает название над текстом и
**убирает первый заголовок** `#` из `task.md`, если он единственный. Поэтому `# Заголовок`
в начале оставляем для читаемости файла, но он должен совпадать с `custom_name`.

**Папки:** `l02_variables/t01_chest` — номер и короткое английское имя. Номера с нулём, чтобы
сортировались.

## 4. Шаблоны шагов

### 📖 Теория

```markdown
# Название шага

Зацепка: проблема из Minecraft, 2–3 предложения. Новый термин — <span class="k-term" title="определение">термин</span>.

<img src="images/x.svg" alt="что на картинке, словами" width="480"/>

## Идея
Объяснение, 1–3 коротких абзаца. Пример кода (до 12 строк).

<div class="k-ru">

«Код по-русски».
</div>

<div class="k-trap">

**Ловушка: …** частая ошибка.
</div>

## Попробуй
1–3 маленьких действия с кодом в редакторе (он лежит в src/Main.java этого шага).

<script src="../../../lesson-kit/kit.js"></script>
```

У теории всегда есть `src/Main.java` с примером из текста: ученик может запустить и поломать.

### ❓ Вопрос

- Один вопрос, 3–5 вариантов. Неверные варианты — **типичные заблуждения**, а не случайный мусор.
- `message_incorrect` не выдаёт ответ, а объясняет, как рассуждать.
- `message_correct` объясняет, **почему** верно (ученик мог угадать).
- Код вопроса лежит в `src/Main.java`: после ответа можно запустить и убедиться.

### 🛠 Задача

```markdown
# Задача: название

Сюжет: 1–2 предложения из Minecraft.

## Условие
1. Что сделать — нумерованным списком.
2. Точные имена переменных и методов, если тест их проверяет.

Должно получиться:
<pre class="k-console">точный вывод</pre>

Что ещё смотрит проверка (если не только вывод): «число 12 должно печататься из переменной».

<div class="hint" title="Наводка">…</div>
<div class="hint" title="Если ошибка такая-то">…</div>
<div class="hint" title="Решение целиком">…</div>

<script src="../../../lesson-kit/kit.js"></script>
```

**Подсказки — лесенкой:** наводка на идею → разбор частой ошибки → решение целиком.
Названия подсказок говорят, когда их открывать («Печатается слово, а не число»).

### 📤 Задача на вывод (output)

Для простых «напечатай вот это», особенно с вводом с клавиатуры: ожидаемый вывод в `test/output.txt`,
ввод — в `test/input.txt`. Тестов писать не нужно, но сообщения об ошибке будут стандартными
(английскими). Поэтому, если важно объяснить ошибку, — лучше 🛠 с тестами.

### 🎮 Действие в IDE (ide)

«Запусти Minecraft», «поставь точку останова». Check засчитывает шаг сразу. В тексте — что должно
получиться и картинка-ориентир, чтобы ученик сам сверил.

## 6. Компоненты (lesson-kit)

Последняя строка каждого `task.md`:

```html
<script src="../../../lesson-kit/kit.js"></script>
```

Скрипт определяет тему IDE, добавляет стили и оживляет интерактив. **Без него всё читается**:
компоненты — это обычный HTML (код, таблица, абзацы). Посмотреть всё вживую — `python3 tools/preview.py`.

### Два вида разметки

- **Компоненты с Markdown внутри** (`k-key`, `k-trap`, `k-mod`, `k-ru`, `k-recap`, `hint`, части
  `k-compare`): после открывающего тега — **пустая строка**, тогда внутри работает Markdown.
- **Компоненты из чистого HTML** (`k-anatomy`, `k-trace`, `k-error`, `k-vars`): внутри **ни одной
  пустой строки**, иначе Markdown разорвёт блок. Внутри пишем HTML (`<b>`, `<code>`), не Markdown.

### Каталог

| Компонент | Зачем | Разметка |
|---|---|---|
| `k-key` | «Запомни»: главное правило шага | `<div class="k-key">` + пустая строка + `**Запомни.** …` |
| `k-trap` | Ловушка: частая ошибка | `<div class="k-trap">` … `**Ловушка: …**` |
| `k-mod` | Связь с модами: где это пригодится | `<div class="k-mod">` … `**В моде пригодится.**` |
| `k-ru` | Код по-русски | `<div class="k-ru">` + пустая строка + «…» |
| `k-console` | Вывод программы | `<pre class="k-console">текст</pre>` |
| `k-term` | Новый термин с определением при наведении | `<span class="k-term" title="определение">слово</span>` |
| `k-anatomy` | Разобрать строку по частям, клик — пояснение | `<span class="t-type" data-label="тип" data-explain="HTML">int</span>` …; классы `t-type`, `t-name`, `t-value`, `t-err` красят по смыслу |
| `k-vars` | Нарисовать переменные-сундуки | `<div class="k-vars">int a = 5; String s = "x"</div>` |
| `k-trace` | Пошаговое выполнение с кнопками | см. ниже |
| `k-error` | Ошибка компилятора | `<div class="k-error"><pre>код</pre><pre class="k-msg">error: …</pre><p><b>Перевод:</b> …</p><p><b>Как чинить:</b> …</p></div>` |
| `k-compare` | «Так / не так» | `<div class="k-compare"><div class="k-good">…</div><div class="k-bad">…</div></div>` |
| `k-recap` | Итог урока | `<div class="k-recap">` + список |
| `k-self` | «Проверь себя» с ответом под катом | `<details class="k-self"><summary>вопрос</summary>` + пустая строка + ответ + `</details>` |
| `alert-*` | Плашки самого плагина (работают и без kit.js) | `<div class="alert alert-primary">` / `alert-warning` / `alert-danger` |
| `hint` | Свёрнутая подсказка плагина | `<div class="hint" title="Название">` + пустая строка + текст |

### k-trace: пошаговое выполнение

```html
<div class="k-trace" data-title="Что происходит с xp">
<pre>int xp = 10;
xp = xp + 5;
System.out.println(xp);</pre>
<table>
<tr><th>Строка</th><th>int xp</th><th>Экран</th><th>Что происходит</th></tr>
<tr><td>1</td><td>10</td><td></td><td>Ставим сундук xp и кладём 10.</td></tr>
<tr><td>2</td><td>15</td><td></td><td>Достаём 10, прибавляем 5, кладём 15.</td></tr>
<tr><td>3</td><td>15</td><td>15</td><td>Печатаем содержимое xp.</td></tr>
</table>
</div>
```

- Первая колонка — номер строки кода, которая выполняется на этом шаге.
- Колонки между первой и «Экраном» — переменные; в заголовке можно указать тип: `int xp`.
  Пустая ячейка — переменной ещё нет.
- «Экран» — что печатает этот шаг (через `println`). Для `print` без перевода строки: `<td data-print>`.
- Последняя колонка — пояснение, можно с HTML.
- Без JavaScript это просто код и таблица трассировки — тоже понятно.

## 7. Картинки

- Рисуем в `tools/images.py` — функция на картинку, добавить её в список `ALL`.
- **Ширина 480** (максимум 560): панель задания узкая, широкая картинка уменьшится и текст станет
  нечитаемым. Шрифт — не меньше 13.5. В `task.md`: `width="480"`.
- Скрипт рисует **две версии**: `x.svg` и `x_dark.svg`. Плагин сам покажет тёмную в тёмной теме.
- Цвета — из палитры темы (`INK`, `MUTED`, `BLUE`…), не вписываем цвета руками. Для кода на
  карточке — `java_tokens(line, on_card=True)`.
- `alt` у `<img>` обязателен и описывает смысл картинки словами.
- После `python3 tools/images.py` запускаем `python3 tools/finalize.py` — он допишет новые
  картинки в `task-info.yaml`.
- ⚠️ Картинки урока 1.1 и раздела 0 нарисованы на 520–680 px — их надо перерисовать под 480.

## 8. Задачи

### Виды

| Вид | Что делает ученик | Пример |
|---|---|---|
| Как в примере | Повторяет показанное с другими данными | «Первая переменная» |
| Заполни пропуск | Пишет часть кода, остальное готово | «Карточка игрока»: печать готова, нужны переменные |
| С нуля | Пишет всё тело `main` | «Уровень опыта» |
| Почини | Находит и исправляет ошибки | «Почини сундуки» |
| Предскажи | Вопрос ❓ «что напечатает» | «Сколько стрел?» |
| Перепиши | Делает работающий код лучше (с 1.7: выдели метод) | — |
| ⭐ Челлендж | Необязательная, сложнее обычного | — |

### Правила

- В условии **точный ожидаемый вывод** в `k-console` и все имена, которые проверяет тест.
- Если тест смотрит не только на вывод — **сказать об этом в условии**.
- Закрываем обходы, которые убивают смысл задачи: напечатать готовую строку вместо переменной,
  посчитать в уме и вписать число. Но не придираемся к стилю.
- Сюжет — из Minecraft, числа — правдоподобные для игры.
- Эталон пишем в `src/Main.java`, область ученика — между `/*[*/` и `/*]*/`, в `task-info.yaml` —
  `offset: AUTO`, `length: AUTO`, потом `python3 tools/finalize.py`.
- `placeholder_text` — подсказка-приглашение («// Напиши код здесь») или, в задаче «почини»,
  сломанный код.

## 9. Тесты

- Каждая задача: **эталон проходит, стартовый код — нет** (`tools/check_starters.py`).
- Один тест — одна мысль. Тест на объявление, тест на способ печати, тест на вывод — отдельно:
  ученик видит все проблемы сразу, каждую своим сообщением.
- Сообщение об ошибке: **что не так, где (номер строки) и что делать**. На русском.
- До урока 1.7 тесты проверяют вывод (`Check.runMain`) и код (`Check.assert…`). С 1.7 —
  ещё и вызывают методы ученика с разными аргументами, это надёжнее вывода.

Помощники `common/src/main/java/course/Check.java`:

| Метод | Что делает |
|---|---|
| `runMain(() -> Main.main(new String[]{}))` | запускает программу, возвращает вывод; если упала — понятное сообщение |
| `assertOutput(ожидаемое, вывод)` | сравнивает построчно; показывает строку и символ, где отличие |
| `assertDeclared("int", "level", "5", "int level = 5;")` | проверяет объявление; если тип или значение не те — укажет строку |
| `assertCode(regex, сообщение)` | в коде (без комментариев) есть такой фрагмент |
| `count(regex)` | сколько раз фрагмент встречается в коде |
| `assertNoNumbers(почему, 12, 9)` | в коде нет «готовых» чисел вне кавычек; укажет строку |
| `code()`, `sourceWithoutComments(path)`, `sourceWithoutStrings(path)` | исходник для своих проверок; номера строк сохранены |

## 10. Как написать урок: порядок работы

1. **План.** Шаги урока уже есть в `PROGRAM.md`. Уточни их по ритму из раздела 3.
2. **Понятия.** Какие понятия урок вводит? Есть ли они в `docs/concepts.yaml`? Нет — добавь.

5. **Код и тесты**: эталон с `/*[*/ … /*]*/`, тесты в `test/Tests.java`.
6. **Ошибки компилятора**: каждый `k-error` проверь настоящим `javac`.
7. **Картинки**: `tools/images.py`, потом `tools/finalize.py`.
8. **Проверки:**
   ```bash
   python3 tools/finalize.py       # плейсхолдеры и список картинок

   python3 tools/preview.py        # превью: build/preview/index.html
   python3 tools/check_starters.py # эталон проходит, старт — нет
   ```
