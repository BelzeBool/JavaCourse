# Деление: целое и дробное

Крипер шипит 30 тиков, а потом взрывается. В секунде 20 тиков — значит, у Стива полторы секунды,
чтобы убежать. Но Java считает иначе:

```java
System.out.println(30 / 20);
```

<pre class="k-console">1</pre>

## Почему 1

Если **оба** числа целые, деление тоже <span class="k-term" title="Деление двух целых чисел: дробная часть отбрасывается">целое</span>:
дробная часть **отрезается**. Не округляется, а просто выбрасывается: `39 / 20` тоже даёт 1, хотя
это почти 2. Для стаков это было удобно, для секунд — нет.

Чтобы получить дробь, хотя бы одно число должно быть дробным: `30 / 20.0` или `30.0 / 20` дают 1.5.

Пройди по шагам и найди, где теряется половина секунды:

<div class="k-trace" data-title="Где теряется дробная часть">
<pre>int fuse = 30;
double seconds = fuse / 20;
System.out.println(seconds);
seconds = fuse / 20.0;
System.out.println(seconds);</pre>

## Приведение типа

Если число лежит в переменной, `.0` к нему не допишешь. Тогда пишут нужный тип в скобках перед
значением — это <span class="k-term" title="Тип в скобках перед значением: (double) fuse, (int) 1.99">приведение типа</span>:

```java
int fuse = 30;
System.out.println((double) fuse / 20);
System.out.println((int) 1.99);
```

<pre class="k-console">1.5
1</pre>

<div class="k-ru">

«Возьми fuse как дробное 30.0 и раздели на 20. Потом возьми 1.99 как целое: дробь отрезается, остаётся 1».
</div>

<div class="k-trap">

**Ловушка: скобки не там.** `(double) (fuse / 20)` даёт 1.0: скобки считаются первыми, целое деление
уже выбросило половину, и только потом 1 превращается в 1.0.
</div>
