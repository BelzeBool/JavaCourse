# Имена и константы

Имя переменной придумываешь ты. Java разрешает почти любое, но есть правила — и есть привычки,
по которым программисты понимают чужой код с первого взгляда.

## Правила: иначе не скомпилируется

- Буквы, цифры, `_` и `$`. **Пробелов нет.**
- Первым символом **не может быть цифра**.
- Нельзя брать слова, которые Java уже занимает сама: `int`, `class`, `public` и другие.
- **Регистр важен**: `diamonds`, `Diamonds` и `DIAMONDS` — три разных имени.

## Привычки: так пишут все

Имя из нескольких слов пишут слитно, каждое следующее слово — с большой буквы. Это называется
**camelCase** — «верблюжий регистр», из-за «горбов» заглавных букв.

Имя должно объяснять, **что лежит в сундуке**. Через неделю `x` ничего не скажет,
а `diamondCount` — скажет. Русские буквы Java тоже разрешает, но так не принято: в чужом коде и в
коде Minecraft все имена английские.

## Константы: сундук с замком

Некоторые значения не меняются никогда: в стак помещается 64 блока, у игрока 20 очков здоровья.
Для них есть слово `final`:

```java
final int MAX_STACK_SIZE = 64;
```

<div class="k-ru">

«Поставь сундук для целого числа `MAX_STACK_SIZE`, положи 64 и запри: менять больше нельзя».
</div>

Имена констант пишут **КАПСОМ_ЧЕРЕЗ_ПОДЧЁРКИВАНИЕ** — сразу видно, что это значение не меняется.

<div class="k-error">
<pre>final int MAX_STACK_SIZE = 64;
MAX_STACK_SIZE = 16;</pre>
<pre class="k-msg">error: cannot assign a value to final variable MAX_STACK_SIZE</pre>
<p><b>Перевод:</b> «нельзя положить значение в final-переменную MAX_STACK_SIZE».</p>
<p><b>Как чинить:</b> если значение должно меняться — это не константа, убери <code>final</code>. Если не должно — не меняй его.</p>
</div>

<div class="k-mod">

**В моде пригодится.** В коде Minecraft и модов константы повсюду: ID мода, максимальная прочность
инструмента, размер стака. Все они записаны именно так — `final` и капсом.
</div>
