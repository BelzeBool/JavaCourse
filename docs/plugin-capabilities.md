# Возможности плагина JetBrains Academy

Что плагин умеет и что из этого берём, чтобы курс был удобнее и красивее.

**Откуда данные.** Сайт с документацией (plugins.jetbrains.com/plugin/10081-jetbrains-academy/docs)
из облачной сессии был недоступен: сетевая политика окружения его блокирует. Поэтому всё ниже
проверено **по исходному коду самого плагина** ([JetBrains/educational-plugin](https://github.com/JetBrains/educational-plugin),
версия 2026.10, коммит `b2ed726` от 05.10.2026) и по официальному шаблону
[jetbrains-academy/java-course-template](https://github.com/jetbrains-academy/java-course-template).
Код — первоисточник: он точнее документации, но названия меню лучше один раз сверить в IDE.

## 1. Текст задания (`task.md`)

### Как он отображается

- `task.md` переводится в HTML парсером Markdown в варианте **GitHub Flavored Markdown**:
  работают таблицы, ~~зачёркивание~~, автоссылки, блоки кода с подсветкой.
- Получившийся HTML вставляется в страницу как есть. Её показывает встроенный **Chromium (JCEF)** —
  это режим по умолчанию в IntelliJ IDEA. Значит, работает почти любой HTML и CSS, включая
  inline-стили (`style="..."`) и SVG-картинки.
- Если JCEF недоступен (редкие сборки, удалённые сессии), плагин откатывается на старый Swing-рендер:
  он понимает только простой HTML и **не показывает SVG**. Для нас это допустимый риск:
  в обычной IntelliJ IDEA JCEF есть. Но не делаем смысл шага зависимым только от картинки:
  у каждой `<img>` есть `alt`, ключевое правило повторено текстом.

### Готовые оформления, которые уже есть в плагине

| Что | Как писать | Где берём |
|---|---|---|
| Свёрнутая подсказка | `<div class="hint" title="Заголовок">…</div>` | Уже используем. Внутри можно Markdown, если после открывающего тега пустая строка |
| Цветная плашка | `<div class="alert alert-primary">…</div>` | Синяя: «запомни», определения |
| | `<div class="alert alert-warning">…</div>` | Жёлтая: частая ошибка, «осторожно» |
| | `<div class="alert alert-danger">…</div>` | Красная: «так делать нельзя» |
| Горячая клавиша **из раскладки ученика** | `&shortcut:EditorDuplicate;` | Плагин подставит сочетание, настроенное у ученика (Windows/Mac/своя раскладка) |
| Формулы | `$x^2$`, `$$...$$` (MathJax) | Скорее всего не понадобится |

Цвета плашек и подсказок плагин сам подстраивает под светлую, тёмную и контрастную тему.

**Берём:** плашки `alert-*` вместо самодельных таблиц «правило / пример» там, где нужно выделить
одно правило; `&shortcut:...;` вместо ручного «Ctrl+D (на Mac ⌘D)». Полезные ID действий:
`EditorDuplicate` (дублировать строку), `ReformatCode` (выровнять код),
`CommentByLineComment` (закомментировать), `MoveLineUp` / `MoveLineDown`,
`RunClass` (запустить), `GotoDeclaration` (перейти к объявлению),
`ShowIntentionActions` (Alt+Enter, быстрые исправления).

### Картинки для светлой и тёмной темы — есть

Плагин сам подменяет картинку в тёмной теме. Порядок поиска (из `taskToolWindow/utils.kt`):

1. атрибут `data-dark-src="images/x_dark.svg"` у `<img>`;
2. атрибут `srcset` у `<img>`;
3. **файл рядом с суффиксом `_dark`**: для `images/hotbar.svg` плагин сам возьмёт
   `images/hotbar_dark.svg`, если такой файл есть в задаче.

**Берём вариант 3:** `tools/images.py` будет генерировать пару `x.svg` + `x_dark.svg`
(тёмная карточка вместо светлой; «окна IDE» внутри и так тёмные). В `task.md` ничего менять
не нужно. Файл `_dark` тоже надо прописать в `task-info.yaml` с `visible: false`.

### Ссылки

| Куда | Как писать |
|---|---|
| Другой шаг курса | `[урок 1.3](course://s01_basics/l03_arithmetic/t01_operators)` — путь по папкам |
| Урок или раздел целиком | `course://s01_basics/l03_arithmetic` |
| Класс или метод Java (откроет документацию в IDE) | `[String](psi_element://java.lang.String)` |
| Окно IDE | `tool_window://Run`, `tool_window://Gradle` |
| Настройки IDE | `settings://...` (ID страницы настроек) |
| Сайт | обычная `https://` ссылка, откроется в браузере |

**Берём:** ссылки «вспомни урок N» через `course://` вместо текста «в уроке 1.3»;
`psi_element://` для первого знакомства с классами стандартной библиотеки;
`tool_window://Gradle` в разделе 3, где появляется Gradle.

## 2. Типы шагов

Из кода (`edu-format/.../courseFormat/tasks`) — для курсов в IntelliJ есть ровно пять типов:

| `type` | Что это | Как проверяется | Где используем |
|---|---|---|---|
| `theory` | Теория, можно с запускаемым кодом | Check не нужен, сразу Next | Объяснения |
| `choice` | Вопрос с вариантами, один или несколько ответов | Плагин сравнивает с `is_correct` (`local_check: true`) | Проверка понимания, «что напечатает» |
| `edu` | Задача с кодом | JUnit-тесты из `test/` | Основной тип задач |
| `output` | Задача «напечатай вот это» | Вывод программы сравнивается с `test/output.txt`; ввод берётся из `test/input.txt` | Уроки про `Scanner` и простые «напечатай»: без кода тестов |
| `ide` | «Сделай что-то в IDE» | Всегда засчитывается по Check | «Запусти Minecraft и вернись», «найди класс Item в исходниках» |

Чего **нет**: заданий на сопоставление, сортировку и таблицы (они есть только на
сайте Hyperskill) и ответа строкой или числом. Их заменяем на `choice` или на `edu` с маленьким
методом, который возвращает ответ.

Полезные поля `task-info.yaml`:

- `placeholders` → `dependency` — область берёт **решение ученика из прошлого шага**.
  Удобно для цепочки задач над одним кодом.
- `solution_hidden: true` — не показывать кнопку «Peek solution» для задачи.
  У нас решение и так лежит в последней подсказке, но для мод-чекпоинтов это пригодится.
- `highlight_level` у файла — можно выключить подсветку ошибок в редакторе (`NONE`).
  Пригодится в задаче «найди ошибки сам», если IDE подсказывает слишком явно.
- `quiz_header` у `choice` — свой заголовок над вариантами.
- `feedback_link` — ссылка «сообщить об ошибке в задаче» (например, на Issues в GitHub).

### Уроки-фреймворки (`type: framework` в `lesson-info.yaml`)

Урок, где все шаги — **одна папка проекта**, и код ученика переходит из шага в шаг.
Ученик видит один проект, который растёт; кнопка Next переносит изменения дальше.

**Берём для мод-чекпоинтов и проектов разделов:** мод растёт от шага к шагу,
как в настоящей разработке.

## 3. Как распространять курс

| Способ | Как | Плюсы | Минусы |
|---|---|---|---|
| **Архив `.zip`** | Автор: правый клик по корню → **Course Creator → Create Course Archive**. Ученик: **File → Learn and Teach → Browse Courses**, там «Open Course from Disk» и выбрать `.zip` | Просто, без регистрации, работает офлайн | Обновления — вручную, новым архивом |
| **GitHub** | Репозиторий с исходниками курса + архив в **Releases** | Бесплатно, история правок, Issues для отзывов, CI проверяет задачи | Ученику всё равно нужен архив: открыть репозиторий напрямую = режим автора с решениями |
| **JetBrains Marketplace** | **Course Creator → Upload Course to Marketplace**, нужен аккаунт JetBrains | Курс ищется прямо в IDE, обновления приходят сами, есть статистика | Публично; нужен вендор-профиль; первая публикация проходит модерацию |
| Coursera / Moodle | Специальные интеграции | — | Нам не нужно |

**Рекомендация:** исходники — в GitHub (уже так), архив курса — в GitHub Releases, пока курс
сырой. Marketplace — когда будут готовы разделы 0–3 и курс пройдёт хотя бы один живой ученик.
В `course-info.yaml` для Marketplace понадобится добавить `vendor` (имя, почта или ссылка)
и иконку `courseIcon.svg` в корне.

Для «режима ученика» у себя: правый клик по корню → **Course Creator → Preview Course**
(в README раньше было «Create Course Preview» — так пункт назывался в старых версиях).

## 4. Что из этого внедрить (сводка)

1. **Тёмные версии картинок** через суффикс `_dark` — доработать `tools/images.py`. Средний объём работы.
2. **Плашки `alert-*`** для правил и частых ошибок — дописать в гайд по стилю, применять в новых уроках.
3. **`&shortcut:…;`** вместо ручных сочетаний клавиш — заменить в уроке 1.1 (5 мест).
4. **`course://` ссылки** между уроками — по мере написания.
5. **Тип `output`** для уроков с `Scanner`: ввод в `test/input.txt`. `build.gradle.kts` уже
   доработан под него: задача `run` теперь настоящая, раньше была пустой заглушкой.
6. **Тип `ide`** для шагов «запусти игру».
7. **Уроки-фреймворки** для мод-чекпоинтов.
8. **CI на GitHub Actions** (`.github/workflows/check.yml`) — уже добавлен: на каждый push проверяет,
   что эталоны проходят тесты, а стартовый код — нет.
